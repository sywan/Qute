# Qute 产品规格 v0.1

日期：2026-11-08

本文件是[初始产品规格草案](初始产品规格草案.md)在「部署到 GitHub Pages」条件下的实施版本。原草案保留为需求背景；其中的活动主机生成、结果 QR 下载和生成式 Q 版效果，改列为后续阶段。

## 产品目标

让任何人不注册、不登录，就能用电脑或手机拍照，或选择相册照片，选定画风后下载图片。用户提供的七人 Q 版团体插画是长期质量目标的参考：未来的生成式版本应保留人数、相对站位、眼镜、发型、服装和手势。

## 新增部署约束

- 代码位于公开仓库 `sywan/Qute` 的根目录。
- 对外入口是 GitHub Project Pages：`https://sywan.github.io/Qute/`。
- 页面是纯静态资源；所有路径必须适用于 `/Qute/` 子路径。
- 访客无需账号，也无需安装 App；手机和电脑浏览器均可打开。
- 不设图像生成服务器、登录服务或持久照片库。用户照片不进入 GitHub 仓库。

GitHub Pages 支持从仓库分支的根目录发布静态站点：[GitHub 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。

## v0.1 范围

1. 用户拍照、上传或拖放一张照片，预览原图。
2. 用户选择五种风格之一，即时看到处理后的图片。
3. 用户下载 PNG；支持的设备可以调用系统分享面板。
4. 图片在当前浏览器内存中处理；刷新或关闭页面后不保留。
5. 对过大的照片和浏览器无法读取的格式提供错误提示。

**实现边界：** 五种风格是本机像素绘图效果，保留照片原有构图。Qute 插画是色块与轮廓效果，不是生成式 Q 版人物重绘。风格名称描述视觉表现，不暗示由某位艺术家制作或授权。

## QR 码与下载的变更

原草案设想由活动主机暂存生成结果，并让同一网络中的设备扫描 QR 码下载。改用 GitHub Pages 后，站点没有接收、保存和分发每位访客照片的后端；一个指向 GitHub Pages 的 QR 码只能打开应用，不能打开保存在另一位访客浏览器里的生成结果。因此 v0.1 使用**本人下载或手机系统分享图片**。结果 QR 下载列为后续功能，需先选择以下一种架构：

| 方案 | 可下载范围 | 需要的新增设施 |
|---|---|---|
| 活动主机临时存储 | 同一现场网络 | 主办方电脑、局域网服务与现场网络配置 |
| 互联网临时存储 | 离场后也可访问 | 额外的在线存储/服务、有效期和滥用控制 |
| 点对点传输 | 双方同时在线 | 配对与连接协商机制，可靠性需实测 |

任何方案都仍可维持**使用者免登录**，但 QR 码必须包含一个接收方实际能访问的结果地址或传输会话。

## 浏览器与隐私

- 相机由浏览器询问授权；若拒绝，用户可改从相册选图。网页内相机需要 HTTPS 或本机安全环境：[MDN 相机说明](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)。
- 输入图片和结果不写入服务端；网页所需的 HTML、CSS、JavaScript 从 GitHub Pages 获取。
- 用户主动按「下载」或「分享」后，图片才离开当前页面，由浏览器或系统处理。
- 上传团体照前应取得照片中其他人的同意。

## 验收标准

- iPhone Safari、Android Chrome、桌面 Chrome/Safari 可以打开 `/Qute/` 且无资源 404。
- 从相册选图后显示原图和结果；切换风格时结果确实变化。
- 相机授权成功时可拍摄；拒绝时仍可上传。
- 下载得到可打开的 PNG；分享不可用时给出下载提示。
- 20 MB 以上的图片被拒绝；页面不向图像处理 API 发送照片。

## v0.2 研究任务

优先验证离线或自托管的图生图模型能否把多人合照真正转成可辨认的 Q 版人物。重点测七人照的人数、站位、个人特征、生成耗时与硬件需求。再依据使用场景选择 QR 下载架构。
